# SVN vs Git: ответы на вопросы

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это указатель на коммит (файл ~40 байт). Создание и переключение
веток мгновенны, потому что вся история хранится локально и не требует
обращения к серверу.

В SVN ветка — это физическая копия директории в центральном репозитории.
Создание ветки и переключение между ними требуют сетевого соединения с
сервером, что медленно и зависит от нагрузки.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система: вся история хранится только на сервере.
Коммит отправляет изменения на сервер, поэтому без соединения он невозможен.
Локально можно лишь изменить файлы в рабочей копии, но они не попадут в
историю, пока не появится связь с сервером.

В Git коммит создаётся локально — в полной копии репозитория, которая есть
у каждого разработчика.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты, которые десятилетиями живут на SVN.
- Госсектор и банки с жёсткими требованиями к централизованному аудиту.
- Большие бинарные файлы (SVN умеет блокировать файлы).
- Простые линейные проекты без активного ветвления.
- Постепенная миграция (SVN + git-svn).
- Обучение новичков (проще модель).
